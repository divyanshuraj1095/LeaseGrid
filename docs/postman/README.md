# Test LeaseGrid with Postman

1. Start the LeaseGrid Compose stack and import the collection and environment JSON files from this folder into Postman. If you already imported the collection, replace the old copy and keep your configured environment. Expand **3. Member lease lifecycle** to see the lease requests. Select **LeaseGrid local** as the active environment. The base URL includes the API prefix. For another deployment, update the entire value.
2. Enter an existing LeaseGrid system administrator’s email and password as local values for `adminEmail` and `adminPassword`. These are application credentials. Public registration creates an ordinary user. On a fresh deployment, have the deployment operator provision a test administrator before running folder 2.
3. Send the requests in **Authentication and access errors** from top to bottom. Registration generates a fresh email and password and saves the user ID. Expect 201 for registration, 409 for the duplicate and 401 for anonymous identity lookup. Member login saves the access token to `jwtToken`. Identity lookup should then succeed, and the attempt to create a team should return 403.
4. Run **Administrator setup** in order. Admin login replaces the active token. Team creation saves the team ID and makes the administrator its owner. Add the registered user as a member and inspect the member list. Create the five-unit CPU pool and set the team quota to three. Both IDs are captured automatically.
5. Run **Member lease lifecycle** in order. After switching back to the member, inspect the team and pool lists. Acquire three units. Allocation returns 201 and saves the lease ID. Replay uses the same idempotency key and payload. Confirm the same lease ID in Test Results. Request one more unit using the separate over-quota request. Expect 409 with `QUOTA_EXCEEDED` even though two pool units remain. Check the pool and list team leases to locate the captured `leaseId`.
6. Read the lease and send renewal before its initial ten minutes expire. The renewal adds ten minutes to the original expiry. Release the lease and check for `RELEASED`. Verify that the team has three remaining quota units and the pool has five available units.
7. For an automated pass, select the whole collection in Collection Runner, choose the same environment and run one iteration in the saved order. Review each status assertion, including the expected error responses. If a token expires, repeat the appropriate login. For the exact assertions, run against the fresh team and pool created by the updated setup. This also applies when upgrading from the older two-unit example. For a fresh lifecycle, restart at registration. Each run creates a distinct user, team, pool and lease record in the selected database. Release returns capacity and retains the history.
